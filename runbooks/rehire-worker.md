# Rehire / Reinstate a Worker

Use the same immutable employee ID only when intentionally restoring the same organizational identity. A newly generated model/Bot instance normally receives a **new employee ID/generation**, even when it fills the same position.

1. Confirm whether this is identity restoration or a new worker.
2. Review prior separation/suspension reason and current policy.
3. Re-evaluate provider/model/tool fit and current position requirements.
4. Do not restore old credentials automatically; issue current scoped access.
5. Reconcile current role, position knowledge and authoritative work state.
6. Record a `rehired` or `reinstated` employment event.
7. Re-run onboarding/evals before restoring broad autonomy.
