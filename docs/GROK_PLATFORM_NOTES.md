# Grok Bot Platform Notes

Last verified: 2026-09-19. xAI Bot-management page last updated 2026-09-18; skills/routines page last updated 2026-09-14.

These are **platform facts and deployment notes**, not constitutional policy. Re-verify before implementing or changing platform-specific automation.

## Current facts that affect HowlFutureWorks

- Bots are durable teammates with role-specific conversations/context.
- xAI recommends the smallest useful roster; existing Bots may suggest or create a focused Bot when a job deserves durable ownership.
- Bots for one account share a cloud computer, including files, browser sessions and sign-ins. Separate Bots are organizational boundaries, not security isolation.
- Hiding a Bot removes it from the main sidebar but **does not pause the Bot or its routines**. Suspension therefore requires routine/action containment, not merely hiding the Bot.
- Duplicating a Bot copies profile/settings, enabled skills, routines and avatar, but does **not** copy conversation history, learned memory or chat attachments. Treat duplication as a configuration shortcut, not employee identity continuation.
- Deleting a Bot removes its active profile, conversation and routines from Grok Bot. Shared-computer files and sign-ins may remain. Offboarding must archive required routine/config evidence first and separately revoke/review external access; deleting the Bot is not access revocation.
- Skills capture reusable methods; routines schedule/event-trigger proven workflows. Prove a workflow first, save it as a skill, then automate it.
- A Bot can currently own up to 50 routines; Grok Bot retains the 20 most recent run records per routine. Durable operational evidence needed by HowlFutureWorks must therefore be copied or referenced into organizational records before platform history rolls off.
- Test runs perform real work. Use safe inputs and preserve approval boundaries.
- Consequential actions such as sending, publishing, purchasing, deleting, permission changes and production changes should stay behind approval boundaries.
- Public Bot templates expose shared configuration such as identity, description, skills and routines. Never publish a HowlFutureWorks Bot template without explicit approval and a review for secrets, internal URLs, customer data, private infrastructure references and other sensitive configuration.
